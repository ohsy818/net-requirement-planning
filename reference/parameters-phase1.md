# 파라미터

호출하는 쪽이 값을 주면 그것을 쓰고, 없으면 기본값을 쓴다.
**기본값을 조직 기준이라고 가정하지 않는다.** 기본값으로 실행했다면 리포트에 그 사실을 적는다.

| 파라미터 | 타입 | 기본값 | 설명 |
|---|---|---|---|
| `critical_categories` | 문자열 배열 | `[]` | 재고량과 무관하게 긴급으로 올릴 품목 분류. 소진 시 작업 중단·안전 위험이 있는 것 |
| `medium_ratio` | 실수 | `0.5` | `현재고 / 재주문점`이 이 값 미만이면 「보통」 |
| `watch_ratio` | 실수 | `1.2` | 미달은 아니지만 재주문점 대비 이 배수 이하면 `watch_items`에 넣는다 |
| `stale_days` | 정수 \| null | `null` | 최종 출고 후 이 일수를 넘긴 과잉 품목을 「장기재고」로 승격. null이면 판정하지 않음 |
| `unit_conversion` | 객체 | `{}` | `{"BOX->EA": 10}` 형태. 없으면 단위 불일치 시 판정 보류 |
| `aggregate_locations` | boolean | `true` | 여러 위치 재고를 합산해 판정할지 |
| `as_of` | 날짜 | 오늘 | 장기재고 판정의 기준일 |

## params.json 예

```json
{
  "critical_categories": [],
  "medium_ratio": 0.5,
  "watch_ratio": 1.2,
  "stale_days": null,
  "unit_conversion": {},
  "aggregate_locations": true
}
```

## 파라미터를 정할 때 생각할 것

**`critical_categories`**
"없으면 오늘 일이 멈추는가"로 판단한다. 비싸다거나 자주 쓴다는 이유로 넣지 않는다.
긴급을 남발하면 긴급이 아무 의미가 없어진다.

**`medium_ratio`**
리드타임이 길수록 이 값을 올린다. 리드타임 30일짜리를 재주문점의 50%까지 기다리면 늦다.
품목군별로 값이 달라야 한다면, 스킬을 품목군별로 나눠 호출한다.

**`watch_ratio`**
이번 회차에 주문하진 않지만 다음 회차엔 올라올 품목을 미리 알리는 용도다.
1.0이면 기능이 꺼진다.

**`aggregate_locations`**
false로 두는 경우는 위치 간 이동이 불가능하거나 비용이 큰 때뿐이다.
기본은 true. 한 위치만 보면 다른 위치 재고를 놓쳐 불필요한 주문이 난다.
