# 대사 규칙

`scripts/reconcile.py`가 구현하는 규칙이다.
스크립트를 쓸 수 없는 환경에서는 이 문서를 그대로 따른다. **같은 결과가 나와야 한다.**

## 1. 미결 물량 집계

```
대상 = open_supply 중 상태 ∈ open_states
       (완료·취소는 open_states 에 넣더라도 항상 제외)

미입고 잔량 = 주문(지시)수량 − 입고(완료)수량      (음수면 0)
```

**부분 입고**는 잔량만 센다. 입고분은 이미 현재고에 반영돼 있으므로
전량을 세면 이중 계산이 된다.

`include_unconfirmed = false`면 미확정 건의 잔량을 0으로 본다.
단, 건 자체는 목록에 남겨 「확정 필요」 판정에는 쓴다.

한 품목에 여러 건이 걸려 있으면 **합산하되 건별로도 남긴다.**
어느 건을 챙겨야 하는지 알아야 한다.

## 2. 순소요량

```
순소요량 = 소요량 − 미입고 잔량        (음수면 0)
```

소요량은 **입력값을 그대로 쓴다.** 현재고에서 다시 계산하지 않는다.

## 3. 제외 판정

```
covered 조건 = 현재고 + 미입고 잔량 ≥ 재주문점
```

순소요량이 0이라도 이 조건을 못 채우면 제외하지 않는다.
목표재고까지 채우지 못하더라도 재주문점만 넘기면 당장은 버틴다는 뜻이다.

`missing_eta_policy = "conservative"`이고 예정일이 없는 건이 섞여 있으면
그 잔량은 **제외 판정에 쓰지 않는다.** (순소요량 계산에는 쓴다)

## 4. 지연 판정

```
지연일수 = as_of − 예정일

지연     = 지연일수 > delay_threshold_days
독촉대상 = 지연일수 ≥ expedite_threshold_days
```

예정일이 없으면 지연 판정을 하지 않고 `missing_eta` 플래그를 남긴다.

## 5. 분류 결정 순서

**순서가 중요하다.** 위에서부터 먼저 맞는 것을 적용한다.

```
1) 미결 건이 있고, 그 중 독촉 임계를 넘긴 건이 있다        → expedite
2) 미결 건이 있고, 모두 미확정 상태다                      → confirm_existing
3) covered 조건을 만족한다                                  → covered
4) 순소요량 > 0                                             → order
5) 그 외 (순소요 0인데 covered 아님)                        → covered + 위험 플래그
```

**1번이 맨 위인 이유** — 지연된 물량이 있는 품목은 새로 주문할 게 아니라
그 건을 챙겨야 한다. 순소요량만 보면 「주문 대상」으로 빠져 중복이 난다.

**2번이 3번보다 위인 이유** — 미확정 건은 확정해야 실제 물량이 된다.
`covered`로 보내면 아무도 확정하지 않고 방치된다.

## 6. 결품 위험

```
결품 위험 = 현재고 == 0  AND  (예정 입고일 > 필요 시점  OR  예정일 없음)
```

`covered`나 `expedite`로 분류됐어도 이 플래그는 따로 붙는다.
"제외했으니 괜찮다"가 항상 참은 아니다.

## 검산

| 항목 | 성립해야 하는 식 |
|---|---|
| 분류 총합 | 네 유형의 합 = 입력 소요 품목 수 |
| 중복 없음 | 한 품목이 두 유형에 들어가지 않음 |
| 순소요 부호 | 모든 순소요량 ≥ 0 |
| order 조건 | `order`인 품목은 모두 순소요량 > 0 |
| covered 조건 | `covered`인 품목은 순소요량 0이거나 재주문점 충족 |
| 잔량 일관성 | 품목별 잔량 = 그 품목 미결 건 잔량의 합 |
| 플래그 일치 | `has_order_candidates` == (`order` 건수 > 0) |

`scripts/reconcile.py`는 이 검산을 실행하고, 하나라도 어긋나면 오류를 낸다.
