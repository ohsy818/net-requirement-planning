# 예외 처리

입력 상태를 남김없이 분류한다. 각 케이스는 `scripts/calculate.py`가 사유 코드로 반환한다.

## 중단 조건

| 상태 | 처리 |
|---|---|
| 조회 결과 0건 | **중단.** 다음 단계로 넘기지 않고 범위 재확인을 요청한다. 빈 리포트를 내면 "부족 없음"으로 오해된다 |

## 판정 불가 (`undetermined_items`)

| 사유 코드 | 상태 | 왜 계산하지 않나 | 필요한 조치 |
|---|---|---|---|
| `no_policy` | 현재고는 있는데 기준재고가 없다 | 비교 대상이 없다 | 재주문점·목표재고 설정 |
| `inverted_policy` | 재주문점 > 목표재고 | 소요량이 음수가 된다. 마스터 오류 | 기준값 정정 |
| `unit_mismatch` | 단위가 다르고 환산 계수가 없다 | 추측 환산은 소요량을 통째로 틀리게 한다 | `unit_conversion`에 계수 추가 |
| `negative_on_hand` | 현재고가 음수 | 전표 누락·이중 출고의 신호 | 재고 실사 |

**판정 불가 품목을 소요 목록에 섞지 않는다.** 별도 표로 보고한다.

## 값을 채워서 진행하는 경우

| 상태 | 처리 | 표기 |
|---|---|---|
| 기준재고는 있는데 현재고 기록이 없다 | 현재고 0으로 보고 판정 | `no_stock_record` 플래그 |
| 같은 품목이 여러 행으로 들어왔다 | 합산 | `merged_rows` 카운트를 보고 |
| 최종 출고일이 없다 | 장기 판정만 생략, 과잉 판정은 정상 수행 | `is_stale = null` |

현재고 기록 없음을 0으로 보는 것은 **보수적 선택**이다.
실제로 재고가 있는데 기록이 빠진 경우라면 불필요한 주문이 생기지만,
반대로 두면 결품이 난다. 다만 **반드시 플래그를 남겨** 사람이 확인할 수 있게 한다.

## 이상 신호 (계산은 하되 보고)

| 상태 | 뜻 | 보고 항목 |
|---|---|---|
| 소요량이 목표재고와 같다 | 현재고 0. 완전 결품 | 긴급도 `critical` |
| 과잉량이 목표재고를 넘는다 | 목표의 2배 이상 보유 | 과잉 발주 이력 의심 |
| 미달 품목 비율이 30% 초과 | 기준재고가 현실과 안 맞거나 공급이 끊겼음 | 기준재고 재검토 권고 |
| 판정 불가가 10% 초과 | 마스터 데이터 정합성 문제 | 마스터 정비 요청 |

마지막 두 개는 개별 품목이 아니라 **데이터 전체의 문제**를 알리는 신호다.
숫자만 내고 넘어가면 매 회차 같은 문제가 반복된다.
